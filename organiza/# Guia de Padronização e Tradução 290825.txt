# Guia de Padronização e Tradução do Projeto

Este documento organiza as informações do arquivo "arquivos para organizar.txt" em um formato claro e estruturado. Ele segue a ordem solicitada: 
1. O que NÃO pode ser alterado (escopo e limites).
2. As traduções permitidas (seletores, variáveis, funções e classes).
3. A padronização de comentários (formatos para CSS e JavaScript, incluindo exemplos e organização).

O foco é manter a integridade do código-fonte, traduzindo apenas comentários e referências simbólicas neles, sem alterar o código em si.

## 1. O Que NÃO Pode Ser Alterado

Conforme as regras do projeto, certos elementos são fixos e não podem ser modificados para evitar quebras de funcionalidade, compatibilidade ou sintaxe. A tabela abaixo resume esses itens, com motivos.

| Item | O que NÃO pode ser alterado | Motivo |
|------|-----------------------------|--------|
| Tags HTML | `<body>`, `<header>`, `<nav>`, `<div>`, etc. | Palavras-chave da linguagem HTML. |
| Atributos HTML | `id`, `class`, `href`, `src`, `alt`, `for`, `disabled`, etc. | Definidos pela especificação HTML. |
| Atributos data-* | `data-livro`, `data-capitulo`, `data-letra`, etc. | Padrão HTML5 – alteração quebra o acesso via `dataset`. |
| Palavras-chave JS | `class`, `function`, `async`, `await`, `let`, `const`, `if`, `else`, etc. | Sintaxe fixa da linguagem JavaScript. |
| APIs do navegador | `document`, `window`, `localStorage`, `console`, `fetch`, `URLSearchParams`, etc. | Globais fixas fornecidas pelo navegador. |
| Métodos e propriedades | `.getElementById()`, `.querySelector()`, `.addEventListener()`, `.textContent`, etc. | Comandos fixos para manipulação de DOM e dados. |
| Eventos | `click`, `change`, `input`, `DOMContentLoaded`, etc. | Nomes de eventos padrão do navegador. |
| Propriedades CSS | `background-color`, `font-size`, `margin-left`, `display`, `position`, etc. | Sintaxe da linguagem CSS. |
| Pseudo-classes / elementos | `:hover`, `:disabled`, `::before`, `::after`, `::-webkit-scrollbar`, etc. | Seletores fixos da linguagem CSS. |
| Nomes de arquivos | `versoes.js`, `concordancia.css`, `index.html`, etc. | Referenciados em scripts, links e chamadas `fetch()`. |

**Regra Final:** Não alterar o código-fonte. Manter referências originais intactas. Traduzir apenas comentários (linha ou bloco) e nomes simbólicos quando mencionados dentro de comentários.

## 2. Lista de Traduções Permitidas

As traduções são autorizadas apenas para comentários e nomes simbólicos listados abaixo, quando referenciados em comentários. Elas seguem padrões de nomenclatura:
- **Classes / IDs CSS:** kebab-case (ex: `.btn-buscar` → `.botao-buscar`).
- **Variáveis JS:** camelCase (ex: `searchTerm` → `termoBusca`).
- **Funções JS:** camelCase (ex: `loadBook` → `carregarLivro`).
- **Classes JS:** PascalCase (ex: `DataManager` → `GerenciadorDados`).

## 3. Padronização de Comentários

Apenas comentários podem ser traduzidos e padronizados. O que pode ser traduzido: comentários (linha ou bloco) e nomes simbólicos listados acima quando mencionados em comentários.

### 3.1 Ordem de Blocos em CSS

- Reset / normalização
- Estrutura básica (body, html, tipografia, cores globais)
- Layouts principais (header, main, footer, sidebar)
- Componentes (cards, botões, formulários)
- Utilitários / media queries

### 3.2 Formato Padrão de Comentários em CSS

Cabeçalho do arquivo:

```css
/*====================================================================*/
/*================== NOME DA SEÇÃO EM MAIÚSCULAS =====================*/
/* Descrição curta do que o bloco faz                                */
/*====================================================================*/
```

Comentário de Bloco:

```css
/* [Bloco] Descrição concisa do propósito do bloco */
.seletor {
    propriedade: valor; /* Explicação do porquê desta linha */
}
```

Exemplo:

```css
/* [Bloco] Estilos do cabeçalho principal */
.cabecalho-superior {
    background: linear-gradient(to right, #333, #555, #777); /* Gradiente horizontal */
    padding: 10px; /* Espaçamento interno */
}
```

### 3.3 Formato Padrão de Comentários em JavaScript

Cabeçalho do arquivo:

```javascript
/*===============================================================================*/
/*               NOME DO MÓDULO EM MAIÚSCULAS                                */
/*===============================================================================*/
/* [Bloco] Descrição do que o bloco faz */
const exemplo = valor; // Explicação da linha
```

Comentário de Bloco:

```javascript
/* [Bloco] Descrição do propósito de uma classe, função ou agrupamento lógico de código. */
function exemploFuncao() {
    // Explicação do que a próxima linha faz.
    const variavel = 10;
}
```

Exemplo:

```javascript
/* [Bloco] Carrega e exibe um versículo específico da Bíblia a partir de um arquivo. */
window.carregarVersiculoEspecifico = async function(livro, capitulo, versiculo) {
    const resposta = await fetch(`caminho/do/arquivo.json`); // Faz a requisição assíncrona.
    const dados = await resposta.json(); // Converte a resposta em JSON.
}
```

**Objetivo Geral:** Manter o código intacto, adicionando ou reformando comentários para clareza e consistência. Verificar arquivos como `versoes_botoeacapitulosversiculo.css`, `versoes_responsivo.css` etc., para aplicar esse padrão.
